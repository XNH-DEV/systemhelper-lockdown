# 安全边界与局限（SECURITY LIMITATIONS）

> 这一份是**自我限制清单**：本项目明确不宣称、不尝试、做不到的事情。

## 1. 硬限制（无 root 物理边界）

| 限制 | 原因 | 影响 |
|---|---|---|
| 不能删除系统分区 APK | `/system` 只读 + dm-verity | 3.9 MB 永久占用 |
| 不能按用户卸载系统应用 | API 35+ 仅 root | `pm uninstall --user` 永远失败 |
| 不能停用系统应用 | HyperOS `PackageManagerServiceImpl` 私有判定 | `pm disable-user` 抛异常 |
| 不能隐藏系统应用 | 需要 `MANAGE_USERS` | `pm hide` 抛异常 |
| 不能撤销特权权限 | install-time 授予 | IMEI 读取无法从权限层阻断 |
| 不能撤销 `ACCESS_LOCAL_NETWORK` | `REVOKE_WHEN_REQUESTED` | 撤销被忽略 |
| 不能做 per-UID 全断网 | 无 root 无 iptables | 前台仍有网络通道 |
| 不能抓包 | 无 root | 无法证明"上传了什么" |

## 2. 本项目的自我约束

- 不加入 root 提权、Bootloader 绕过、签名伪造、系统分区强制修改、漏洞利用
- 不使用未公开 API 做越权（例如尝试绕过 `shouldRestrictEnabledSettingsChange`）
- 不自动批量操作未知系统应用
- 不把用户级卸载说成"彻底删除"
- 不把 `suspend` 说成"硬件级隔离"
- 不把后台限制说成"全局断网"

## 3. 不可宣称的结论

| 禁止的说法 | 为什么 |
|---|---|
| "100% 阻止监听" | 系统级间接调用路径未穷尽 |
| "永久零联网" | 只证了观测窗口内 0 增量 |
| "完全消灭数据采集" | 特权权限仍在，靠"不执行"兜底 |
| "任何情况下不影响系统" | 未做全 ROM 矩阵测试 |
| "所有 HyperOS 版本都验证过" | 只测了一台设备 |

## 4. 已知盲区

| 盲区 | 说明 |
|---|---|
| 服务端是否收到数据 | 设备侧无证据 |
| 历史累计流量 | Settings 计数器与 netstats 不同源 |
| OTA 后的状态 | 未实测，按"可能全部恢复"处理 |
| 系统服务间接调用 | 例如 carrier 配置读取它的 Provider（本包无 Provider，但同类组件可能有） |
| 多用户/XSpace | 只验证了 user 0 与 999 的安装状态 |

## 5. 误用风险

| 误用 | 后果 |
|---|---|
| 对 `com.qualcomm.*` 执行处置 | 可能破坏基带/网络服务 → 保护名单已硬拦 |
| 把本项目用于他人设备 | 违反使用范围（只允许自有/明确授权设备） |
| 把快照跨设备使用 | `rollback.sh` 有包名/用户校验，会拒绝 |
| 在 CI 里连真机 | 测试全部走 mock，不允许真机 |

## 6. 供应链

- 仓库不包含任何第三方二进制（`.apk` 已在 `.gitignore`）
- 文档中的包名、证书 DN、域名来自公开 APK 元数据，用于描述问题，不代表厂商立场
- 许可证 MIT

## 7. 免责的准确表述

本工具只能限制**已经确认能够控制**的 Android 访问路径。它在当前测试设备上达成的是：
"零进程、零联网（观测窗口内）、零通知、零闹钟、权限已撤、数据已清"。
它**不保证**在其他 ROM、其他权限机制、其他系统服务条件下达到同样效果。
